# Classic Launch and mod profiles

Classic Launch loads selected Standard mods in their catalog order through Majesty's ordinary active mod list. The Manager asks for confirmation because overlapping mods can cause errors, crashes or broken saves. Merge choices and their generated runtime features are omitted. Installed Quality of Life helpers and available quests continue to work. The selected-mod restore buffer supports up to 256 active components on Steam Default, Steam beta2 and GOG. GOG also registers selected Standard manifests using its existing stock loader.

The profile menu beside Launch stores up to five named setups. Save current selections to create a profile, then select it from this menu to restore its selections and preferred-mod choices. Each successful Prepare retains a copy of that profile's generated package. Selecting a saved profile restores that package without compiling it again. Changes to installed inputs can still require a fresh Prepare under the normal validation. Profiles are stored privately beneath the Manager settings folder.

Changed selections prompt Update profile, Save as new profile, or Cancel when preparing or launching. Classic Launch mode, the selected Game Install and Play all quests with expansion content are part of the saved setup. Switching profiles restores all three, rechecks Quality of Life for the chosen installation, and updates the installation and quest controls. An unavailable or unsupported saved executable prevents the switch before changing the active setup. Existing profiles created before these settings were recorded will prompt for an update to capture the current values. Quest filtering is currently unavailable on Steam, so downloaded quests continue to appear in Majesty's quest list.

Scans record the current package metadata. A new item remains disabled and receives a New pill. Changed packages receive Updated while preserving their existing selection. Items with pills sort first and their tab shows a gold dot. Indicators expire on the next scan, including the next application startup. The first inventory establishes the baseline.

History beneath the Manager version opens brief patch summaries, newest first. A changed Manager version receives the same one-scan gold indicator using the existing catalog baseline file. Opening History does not extend or reset the indicator lifetime. This is local version comparison and needs no network check. UI-only implementation relevance check used the shared research map and knowledge graph f2644580d33ad98703361cd8fc88c825068161ef; no native game contract or mapping changes are needed.

The profile picker uses the installation-completion handler to refresh the restored setup. Updating the Classic Launch and expansion-content controls during restoration suppresses their edit signals, so displaying saved settings does not write them again. A failed profile scan disables launch until a successful scan. UI regressions click Use selected profile in both directions and check the selected profile, controls and failure handling using disposable fixtures.

Implementation references include the stock Active-list construction, dirty flag and canonical commit documented by the Remember Active Mods utility. The larger buffer relocates the existing complete restore routine's owned scratch references after comparing its full payload with the bundled version. Source parsing, GUID lookup, duplicate suppression, insertion, commit ordering and cleanup are preserved. Profile copies use the existing generated-output lock and atomic publication mechanism. The stock research map and knowledge graph f2644580d33ad98703361cd8fc88c825068161ef were consulted for these existing lifecycle references.

Native regression fixtures execute the relocated stock restore payload in a disposable fixture process with mocked file and list helpers. They cover all three executable profiles, more than 26 mods, order preservation, missing IDs, repeat restores and rejection of a changed payload. Gameplay acceptance remains separate.
