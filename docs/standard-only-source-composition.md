# Source-backed Standard composition

Standard packages retain their native classification and resources. Normal
Prepare can now emit function deltas when selected Standard sources contain
disjoint edits to a common stock function. Classic Launch retains native-only
load order and does not require this output. No dummy Merge source is added.

The existing catalog inventory identifies potential overlap. Planning snapshots
each relevant provider once and checks whether its effective compiled definition
has source inputs; it does not compile sources. A Standard-only composition plan
then uses the existing stock input fingerprint, preparation, saved-profile,
generated-output lock and launch/cache paths. A lone Standard or a selection
without source-backed overlap retains the direct-launch path.

During Prepare, declared Source files and exact-name/sole projects keep their
existing precedence. If a target has no filename-matched project, discovery
compares candidate projects' complete parsed definition inventories with the
actual BCD declaration index. Only one unambiguous match is inferred. Candidate
projects remain inside the component boundary; foreign manifests and links are
excluded. Unrelated source files are watched for discovery invalidation but do
not become emitted inputs. No batch file is interpreted or executed. This is
discovery evidence only: the existing compiler/bytecode proof still gates use.

The existing structural merger and preference resolver combine stock-function
edits. The selected Standard load order supplies precedence for incompatible
edits. Opaque, source-mismatched, ancestor-less and ABI-incompatible definitions
retain their native winner. Only a different, proven composed function is
emitted. Existing generated-feature definitions are excluded from this pass and
retain their own reconciliation. Prototypes, other resources, initializer guards,
attribute schemas, defaults and scheduling calls are not rewritten by this rule.
Native Standard functions and helpers remain independently loaded.

A displaced opaque definition is not restored or used as a contributor. It
does not block combining other proven contributors when the actual native winner
is also proven. Compiler proof for this optional path is attempted once per
module per bundle, with a ten-second budget. A failed optional proof retains
native precedence; it is never repeatedly retried for every function or scope.
Required generated-feature proof keeps its existing strict behavior and budget.
Dependency closure checks actual compiled ownership for native linkage presence;
it does not require a helper's source merely because another function calls it.
Replacing that helper still requires the existing full source/BCD proof.

This does not make semantically incompatible initialization code compatible.
An author who uses a shared marker to skip unrelated missing attributes must
correct that source contract. Such a source correction can itself be an ordinary
independent Standard GPL package with matching Source and BCD, rather than a
Manager-specific named integration.

`script_function.palace_birth`, `engine_function.runthread` with their static
read-grade/source limitations; research shared-map checkpoint21434,

three-profile BCD reader witnesses. Existing SDK Base/MX Building_Births,
stock comparison sources, native compiled ownership and exact project/BCD proofs
are the primary inputs. No new native mapping, timer or runtime dispatch is used.

Focused regressions cover ambiguous inventories, discovery invalidation,
component boundaries, unsupported source proof, real conflicts, generated-feature
exclusion and Standard-only planning. Actual source/BCD and isolated compiler
checks are private under `local/panel-engine-host`; they construct no Manager
package/profile and do not claim native gameplay acceptance.

The November10 local compatibility update belongs in the canonical beta tester
at `dist/Majesty Mod Manager`, independently of the Witch Hunter panel alpha.
Its build inputs are the byte-verified beta source at df6c995 plus only the eight
generic Python source-recovery/composition/planning/XML/UI files. The existing beta
payload, native runtime, panel modules and profile data are retained byte for
byte. Experimental reward declarations, revision2 panel handoff changes,
completed-stage runtime changes and capped panel diagnostics remain in alpha.
The beta plan schema stays28, rather than importing alpha's reward-output bump.
Private selective source/package receipts and the exact source delta are under
`local/standard-compatibility-beta`; the working development source is preserved.

Saved Standard preferences determine the effective native order. Standard-only
source composition derives pair precedence from that same order internally;
it does not ask for a second source review. This does not grant automatic
preferences to newly selected packages or waive source/BCD proof. ComTesting's
settings correction and inactive alpha selection copy are separately recorded
under `local/panel-engine-host/comtesting-choice-repair`.

The first beta scan exposed a planner-only omission: the source-only admission
branch reached private-activity discovery with no Merge inventories initialized.
The planner now starts with an empty inventory tuple and runs private-activity
discovery only when Merge inputs exist. Standard-only plans still capture their
required stock composition fingerprint. The regression exercises complete
`create_build_plan` with a game path, not merely the lower-level source-input
refresh; selective beta source/package checks also scan the actual44-mod
ComTesting selection against Public/beta2/GOG fixture identities and the proper
stock data. No prepared profile is constructed by those checks.

The XML follow-up distinguishes a strict authored Merge document from an
independently loaded Standard file. `parse_native_descriptions` projects only
direct Description children; Language siblings and nested quest metadata remain
with their original native file and are not emitted by that projection. The
strict Merge parser still rejects unsupported top-level record families, and
both entry points retain XML safety and Description-record validation. A
Standard-only script overlay bypasses native XML reconciliation altogether and
emits no replacement XML. Mixed Merge/Standard setups can still reconcile the
recognized Description records in native order.

The actual selected XML payloads are now exercised for both dataset scopes,
along with production description preparation on all three profiles, in the
selective beta source/package checks. KG `mechanic.unit-description-xml` and
the research `dataset-application.md` / `dataset-strings.md` were consulted with
their source/build qualifications; Language XML and CAM STRT remain distinct.
This fix introduces no native address or inferred cross-version native behavior:
original Standard resources remain loaded, while only typed Description records
enter the existing composition algorithm.
