# 0.3.11 integration evidence and limits

User authorized promotion of the current test Manager with bounded logging and
custom-hero support, release-only commit/push, and Workshop staging on November 3.

Knowledge Graph consulted: f2644580d33ad98703361cd8fc88c825068161ef,
README and existing registration evidence exclusions; research shared-map
checkpoint 14043. No new addresses or binary research are introduced here.
Primary source: runtime/AuditedBeta2.cpp startup certificate;
runtime/AttackObservationRuntime.cpp and CheckedPlacementRuntime.cpp installers;
docs/sdk-bytecode-runtime-admission.md and existing three-profile fixtures.

The shared observer's startup certificate checks that no world is attached.
That is required for first hook installation, but not for callbacks registered
again into a new GPL table. The installed path now checks its selected profile,
owner thread and fault state without re-running the pre-world certificate.
Checked placement likewise reuses its installed profile and re-registers bindings.
ObserverReregistrationTests covers interception-only and custom-hero bindings;
PlacementReregistrationTests covers placement callbacks and invalid state.
NativeRegistrationLifecycleTests exercises actual guarded installer windows,
re-registration with a world present, and first-fault bytecode ownership evidence.

All new contracts are generic and optional. Existing release package tests retain
all three installed guild packages, preference permutations, standard-script mix,
and art fixtures. Full custom-hero checks join the release gate rather than
replacing its existing coverage. Packaged receipts enforce source/data identity.

The October 29 reporter's original first fault is unavailable: that released DLL
did not capture it. The startup correction is independently demonstrated, not
claimed as that reporter's diagnosed root cause. The new reporting retains the
first fault for future failures. Fresh live acceptance across every quest,
save/load, animation and UI combination remains distinct from offline tests.

Retired bespoke development combination adapters were excluded from promotion.
The release retains its existing compatibility registry; current custom-hero
packages use the generic feature contracts and preferred-mod conflict choices.
