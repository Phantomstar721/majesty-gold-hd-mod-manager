# Stock hero combat policy

`stock.hero-combat-policy.v1` is a source-composition capability. Required fields:
`feature_key`, `hero_title`, `marker_attribute`, `paired_accuracy` (boolean).
Optional `melee_accuracy_per_level` and `ranged_accuracy_per_level` are integer
increments from 1 through 98, each defaulting to 1. Nondefault increments require
`paired_accuracy: true`. Both accuracy skills progress regardless of held weapon.
For example, 2/1 gives +2 melee and +1 ranged on level gain, -2/-1 on level loss.
Each operation is bounded by the stock upper98/lower1 threshold; a step crossing
the bound applies only the remaining difference. Already-outside values are not
reset. Existing clients omit these fields and retain their original behavior.

Optional owned GPL callbacks:

- `level_callback_symbol(agent Hero, integer Direction)`: no return value.
- `confidence_callback_symbol(agent Hero) is integer`.
- `hostile_multiplier_callback_symbol(agent Hero, agent Hostile) is float`.

Eligibility requires a valid living actor, exact private Title and an existing
true marker. Nonparticipating heroes retain stock calculations. Paired accuracy
extends the two stock attack-mode gates, retaining each stock <98 / >1 condition.
The default keeps the stock +1 / -1 operation; custom increments replace that
operation only for the matching private policy. No load observer, migration, replay or compensating ledger
is installed. Existing accuracy values are not backfilled.

Level callbacks run once at the end of the stock stat helper, with +1 or -1.
Stock ordinary leveling and forced advancement already increment the level before
calling the helper; the drain helper decrements it internally. A guild needing
birth initialization calls its own callback with Direction 0 from its existing
birth source. Manager does not intercept construction or load.

Confidence adds to the stock terminal spell_extra_value accumulator. The hostile
callback scales only that hostile's armor/to-hit-adjusted effective HP term in
the existing list_eval loop. Both target_eval and should_I_run already call this
stock routine. It does not mutate enemy_estimation or replace the group score.
Callbacks must not recursively call those evaluation paths.

Generated edits enter normal preferred-mod review as contributions owned by
their declaring packages. An incompatible preferred source wins without the
losing contribution being reapplied afterward. Invalid owned callbacks remain
declaration errors, not a reason to change unrelated source.

The damage contribution interface also accepts `spell_damage_scale(agent Source,
agent Attacker, agent Defender, integer Amount) is integer`. It runs after stock
magic armor and direct-only reductions, before the single stock HP adjustment,
for direct and periodic damage. Negative output is clamped to zero. Direct-only
final notifications see the scaled value; periodic damage does not gain those
notifications or direct-only reductions.

script_function.list_eval, script_function.level_up_stats_increase,

Research source pairs consulted: level-up-stats-source-pair-20261011,

spell-extra-source-pair-20261011 and retreat-decision-source-pair-20261011.
Native actor construction/cleanup/providers remain outside this change.

Both base and expansion generated sources are compiler-checked. This capability
adds no executable offsets or native hooks; Public, beta2 and GOG use the existing
GPL/runtime support, checked by both release and development three-profile gates. Offline
source/compiler checks do not constitute in-game acceptance.

`scripts/check_hero_combat_candidate.py <candidate>` checks owner file hashes,
actual package admission and the production GPL review/finish path for these
combat/damage features, compiling only temporary source output for both datasets.
It never constructs a merged profile. Other candidate native features are not
regenerated by that narrow check.
