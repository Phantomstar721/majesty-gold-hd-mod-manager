# Tested panel engine integration into beta

The user's November 9 acceptance and integration request was relayed by owner
chat 01a1b6a1-6424-78c1-97e2-0117e1938b04. This integrates the tested engine,
script service, dependency discovery, native component admission, typed panel
references and research return correction. The reward-selection composition
proposal remains separate and unimplemented.

Beta retains MajestyModManager state, normal named profiles, the selected
MajestyHD.exe, ordinary remembered-mod paths and Majesty Mod Manager - Merged.
No alpha state, UIAlfa layouts or sibling executable is adopted. Alpha remains
explicitly isolated through its edition flag. Engine support has a separate
native build define, CAM_PANEL_ENGINE_SUPPORT; CAM_PANEL_ENGINE_ALPHA controls
only the alpha's remembered-list isolation.

Engine installation/removal remains an explicit user QoL action. The pure
installer validates version-specific complete guards and an owned descriptor;
the publisher checks the selected filename, reviewed input hash, candidate
hash and write lock before atomic replacement. Removing either service
preserves the other and existing QoL patches. Ordinary launches do not install
an engine or infer engine ownership from a familiar panel ID. The native
per-instance ownership ABI remains authoritative for shared dispatch.

Recognized loaded SMNU/STRT data proves the panel dependency. Arbitrary native
calls inside a compiled-only BCD do not yet provide a verified call contract;
these remain explicitly unresolved rather than guessed. A package can declare
both external services, or the player can install both optional rows manually.
No Manager definition is required merely to load a native Standard component.
The untouched native Workshop fixture was admitted as Standard with its
MajestyExpansion scope; the private evidence receipt is
`local/panel-engine-beta/original-native-package.json`.

Regression requirements include both install/removal orders on all three
disposable game fixtures alongside existing helpers and native UI layouts;
ordinary beta paths and optional credits; locked/changed publication rejection;
the existing native ownership, descriptor, persistence and profile checks; and
fresh source/frozen startup with and without both services. Cold-start checks
use private settings, offscreen Qt and synthetic launch snapshots. None create
a merged profile or start Majesty. Existing package and launch tests cover
Standard/Merge/Classic and named profiles. Live acceptance remains distinct.
