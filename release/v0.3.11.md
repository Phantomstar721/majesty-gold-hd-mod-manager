# Majesty Mod Manager 0.3.11

This update adds reusable custom-hero, ability, research, and item support while
retaining compatibility with existing packages. Supported game versions are
Steam Default 1.5.2.24, Steam beta2 1.5.2.28, and GOG 1.5.2.28.

- Corrects repeated script registration in the shared projectile runtime. A
  startup-only check no longer incorrectly rejects registration while an old
  quest world is still present. Build, thread, and ownership checks remain.
- Corrects false script-ownership failures when projectile interception is used
  alongside ordinary mods. Ownership now covers only required native-feature
  callbacks and API names, without applying base-game-only claims to expansion
  games. Required callbacks are checked in both game modes during Prepare.
- Adds bounded automatic first-failure reporting and **Save Support Report**.
  Reports include launch identities and recent failure context, without
  continuous combat tracing or full-memory dumps. Logs rotate instead of
  accumulating indefinitely; reports stay local until the player shares them.
- Supports registered hero combat policies, paired weapon progression,
  projectile observation, checked spell placement and travel, and timed visual
  effects through guarded per-version runtime profiles.
- Supports building employment, queued research transactions, secondary-panel
  eligibility and cooldown display, saved attribute rows, status events, and
  temporary attack incentives independent of player reward flags.
- Retains custom inventory names, icons and hover text, independent Manager/game
  version labels, generic script/XML/art/sound conflict choices, and the previous
  SDK bytecode ownership correction.
- Reuses parsed inputs within Prepare and keeps original/expansion description
  processing separate. Existing preferences and old package declarations retain
  their defaults; new capabilities activate only when selected content needs them.

Close Majesty and the Manager before updating. Keep the entire application
folder together. Reopen the Manager and choose **Prepare Again** before launching.
This update does not supply custom guild content; update those packages separately.

If a failure occurs, use **Save Support Report** and send that ZIP with a short
account of what happened. Reports may contain local paths and mod names. Nothing
is uploaded automatically. Bounded reports improve evidence but cannot guarantee
capture after a force-kill, power loss or every native crash.

Release verification reads installed package inputs and all three executable
fixtures, checks production admission/composition in disposable tests, and tests
packaged code against source. Native lifecycle fixtures use private memory only.
These checks are not a claim of fresh in-game acceptance on all three builds.
